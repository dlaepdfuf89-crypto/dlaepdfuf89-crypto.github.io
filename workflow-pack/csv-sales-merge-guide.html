거래 CSV 파일 여러 개 합치기부터 거래처·상품별 매출 집계까지

매일 내려받는 거래 CSV가 여러 개로 나뉘어 있다면 단순히 행을 붙이는 것만으로는 집계가 완성되지 않습니다. 필수 열이 같은지, 금액 계산 규칙이 일치하는지, 잘못된 날짜나 누락된 수량이 끼어 있지 않은지 먼저 확인해야 합니다.

핵심 순서 — ① 동일한 열 구성 확인 → ② 날짜·수량·단가 검증 → ③ 정상 행 합치기 → ④ 거래처·상품별 합계 → ⑤ 제외한 오류 행 별도 보존

1. 합치기 전에 CSV 열 구성을 확인하세요

예를 들어 일별 거래 CSV에 거래일, 거래처코드, 거래처, 상품코드, 상품명, 수량, 단가가 같은 순서로 존재한다고 가정합니다. 이름이 다르거나 의미가 다른 열을 그대로 이어 붙이면 거래처와 상품이 잘못 묶일 수 있습니다.

먼저 UTF-8과 CP949 등 문자 인코딩을 확인하고, 파일마다 열 이름과 숫자·날짜 규칙이 일치하는지 비교해야 합니다. XLSX와 CSV는 서로 다른 파일 형식이므로 구분합니다.

2. 원본 데이터를 조용히 수정하지 말고 검증하세요

  • 날짜: 2026-02-30처럼 실제로 존재하지 않는 날짜는 유효하지 않습니다.
  • 수량: 빈칸은 0과 다릅니다. 정해진 규칙이 없다면 임의로 0으로 바꾸지 않습니다.
  • 단가·금액: 수량과 단가의 데이터 유형, 세금 포함 여부를 확인합니다.
  • 거래처·상품 식별: 같은 코드에 서로 다른 이름이 연결되면 검토 대상으로 표시합니다.
  • 중복: 동일 파일 중복 선택과 거래 자체의 중복 여부를 별도로 구분합니다.

취소·반품·할인·환불 거래는 회사마다 의미가 달라, 합계에 반영할 규칙을 담당자가 먼저 결정해야 합니다.

3. 정상 거래 금액을 계산하고 거래처·상품별로 묶습니다

가상 샘플에서는 정상 3행이 A상사 X상품 2개 × 10,000원, A상사 X상품 3개 × 10,000원, B상사 Y상품 1개 × 5,000원입니다.

거래처상품총수량총금액
A상사X상품550,000원
B상사Y상품15,000원
정상 거래 합계655,000원

정상 거래는 총 3행이며, 별도의 오류 2행(수량 누락·유효하지 않은 날짜)은 이 합계에 넣지 않았습니다. 결과는 따라서 부분 집계입니다. 오류 행까지 포함한 원래 전체 매출을 55,000원으로 단정하면 안 됩니다.
