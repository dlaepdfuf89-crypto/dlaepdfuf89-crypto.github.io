실제 무료 평가판 화면

  1. 압축을 풀고 DeliveryProofEvaluation 폴더 안의 DeliveryProofEvaluation.exe를 실행합니다.
  2. Approved folder에서 담당자가 이미 승인한 영상 폴더를 선택합니다.
  3. Save manifest 위치를 입력한 뒤 Capture Approved Baseline을 누릅니다.
  4. Baseline manifest와 별도 Final delivery folder, Report parent folder를 선택합니다.
  5. Verify Delivery를 누릅니다. 기술 검수 PASS일 때만 ZIP을 생성합니다.

무료 평가판 사용 중 자주 나오는 질문

어떤 폴더로 기준본을 만들어야 하나요?

먼저 담당자나 고객에게 별도로 승인받은 영상 내보내기 파일을 모아 Approved folder로 선택하세요. DeliveryProof는 사람의 승인을 대신하지 않습니다. 기준 JSON은 승인 영상 폴더 밖에 보관하는 것이 좋습니다.

기준본과 최종 납품 폴더가 같아도 되나요?

아니요. 기준본은 이미 승인된 파일이고 Final delivery folder는 실제로 전달할 별도 폴더여야 합니다. 승인본으로 기준선을 만든 다음 최종 납품본을 선택하여 Verify Delivery를 실행합니다.

동일한 승인본으로 다음 작업을 검사할 수 있나요?

승인 기준본이 여전히 유효하면 Quick Verify Recent Baseline을 사용해 다른 최종 납품 폴더를 선택하고 다시 검사할 수 있습니다. 고객 승인 내용이 변경됐다면 기존 기준본을 무조건 재사용하지 말고 새로운 승인본을 확보해야 합니다.

검수에 FAIL이 나오면 무료 횟수가 줄어드나요?

아닙니다. 무료 R3 한도는 성공적으로 생성된 납품 ZIP 5건을 기준으로 합니다. FAIL 또는 NEEDS_REVIEW처럼 ZIP 생성이 차단된 시도는 성공 횟수에 포함되지 않습니다. 원인과 파일을 확인한 뒤 재검수하세요.

얼마나 시간을 절약했는지 자동으로 알려주나요?

프로그램 내부에서 관측한 실행 시간만으로 전체 작업 절감 시간을 입증할 수 없습니다. Complete Trial Evidence에서 기존 방식과 DeliveryProof 방식의 준비·검수·재작업·패키징 전체 시간을 각각 직접 기록해야 합니다. 고객의 결제 여부 체크 역시 실제 판매를 증명하는 자료는 아닙니다.

보안 경고가 나타나거나 회사 PC에서 막히면 어떻게 하나요?

R3 실행 파일은 코드서명되지 않았습니다. Windows 10 x64 개발자 환경에서만 실행을 검증했고 Windows 11과 관리형 회사 PC는 독립 검증하지 않았습니다. SmartScreen이나 회사 보안 정책을 우회하지 말고 IT 담당자에게 확인하세요.
