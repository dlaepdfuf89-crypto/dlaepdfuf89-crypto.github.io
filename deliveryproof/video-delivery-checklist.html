Final video delivery checklist: prevent the wrong export reaching the client

For campaign teams, podcast editors, social-content agencies and post-production studios, the highest-risk handoff mistake is often mundane: an old export, the wrong aspect ratio, an omitted video or an unexpected preview file. A pre-delivery check should be repeatable, clear and separate from creative approval.

Key distinction: technical file checks can confirm that a video matches an existing approved file. They do not establish that the creative team actually approved that file or that its captions and audio content are correct.

1. Freeze a human-approved baseline first

Create an approved_exports folder only after the real editor/client signs off. Preserve the original relative paths and filenames. Prefer separate directories for language and aspect ratios, e.g., en/landscape_15s.mp4, en/portrait_15s.mp4, ko/landscape_15s.mp4. Capture a manifest outside the baseline folder containing file path, SHA-256 and declared metadata. Merely using a filename ending in FINAL is not approval.

2. Compare exact folder inventory

List the files expected for delivery. For every expected video, verify its path exists in the final folder. Flag missing files and unexpected extras. Extra files can expose rough cuts or confidential previews. On Windows, Get-ChildItem -Recurse -File lists folder inventory; compare relative paths, not just matching base filenames.

3. Verify file-byte hashes (not only names)

Two videos named approved_final.mp4 may have different actual bytes. For a manual Windows check:

Get-FileHash -Algorithm SHA256 "C:\\approved_exports\\en\\landscape_15s.mp4"
Get-FileHash -Algorithm SHA256 "C:\\delivery\\en\\landscape_15s.mp4"

Same bytes mean identical file contents relative to the chosen baseline; hashes cannot tell you whether captions, dialogue, license rights or customer approvals were correct to begin with.

4. Verify the technical metadata you actually promised

For every final video verify declared width × height, runtime, average frame rate and required audio-stream presence. A 9:16 vertical social video and 16:9 horizontal master should not be confused. Check content by watching/listening separately: technical metadata cannot tell you if subtitle text is correct, if a voice-over is in the required language, if color grades match reference, or if the audience hears a corrupted audio segment.

5. Define a fail-closed ZIP handoff

Do not package files merely because the script ran. Prevent delivery packaging when an expected video is missing, extra content appears, declared specs mismatch, or the comparison is incomplete. Review errors, fix the export, and rerun verification. Include a machine-readable or human-readable report with the delivery package when that fits your client's workflow.

6. Do not skip filesystem and security risks

Reject file references that escape the selected folder (.. traversal or absolute paths), symbolic links/junctions, unreadable folders and unsupported files. Treat metadata probe failures or timeouts as review errors, not a green light. Never disable enterprise endpoint security just to try a small unsigned utility.

7. Measure the actual cost of introducing a tool

Time savings are only real if baseline preparation + execution + investigating warnings + fixing files + packaging beats your current routine. Compare the same completed job across both methods. If your current QA is faster and accurate enough, adding another tool may not be justified. Keep the comparison honest.
