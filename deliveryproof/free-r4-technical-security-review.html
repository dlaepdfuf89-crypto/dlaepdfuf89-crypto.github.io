Input paths and failure behavior (R4 source review)

The following describes publisher inspection of the R4 evaluation Python source, not independent binary certification or an enterprise endpoint security audit.

  • File paths: Approved manifest entries must be portable relative paths. The implementation rejects absolute or escaping paths, unsafe Windows names, duplicate JSON keys, and Windows case-insensitive filename collisions.
  • Symbolic links and junctions: The implementation rejects symbolic links, Windows junctions, and special files in the inspected input tree. Resolved candidate files must remain inside the selected input root.
  • Missing or inaccessible inputs: An unreadable or incompletely traversed input tree raises a check error rather than silently receiving a technical PASS. Failed required checks prevent producing a verified delivery ZIP.
  • Metadata failures: Local MediaInfo / ffprobe probing treats missing, incomplete, corrupt, or unsupported metadata and process launch/timeout failures as errors. The examined source sets a 15-second per-file metadata probe limit and also enforces an overall execution deadline.

Security boundary: These are source-level observations; they do not establish that every frozen native dependency has undergone independent security testing, that all environments are supported, or that the complete executable is certified to make no network connections.
